## 1. Project Overview

The **Student Information Management System (SIMS)** is a responsive web application developed collaboratively by our team to register students and manage student records.

### Core Features
- **Student Registration:** An intuitive input form allowing users to submit a student's full name, matriculation number, and academic programme.
- **Records Display:** An interactive table presenting registered students with automated numbering and dynamic record counting.
- **Client-Side Validation & Feedback:** Instant feedback alerts, duplicate matriculation number prevention, and automated form resetting upon submission.
- **Responsive Interface:** A clean, modern two-column layout that shifts into a mobile-friendly view on smaller screens.

## 4. Question 4: Merge Conflict Resolution Report

### 4.1 Definition and Possible Causes of a Merge Conflict (Task 4a)
- **Definition:** A merge conflict occurs in Git when two different branches make competing, contradictory modifications to the same lines of code within a file (or when one branch edits a file that another branch deleted), preventing Git from automatically combining them.
- **Possible Cause:** A common cause occurs when two developers (e.g., Member A adding form elements and Member B adding table elements to `index.html`) both edit the same section between lines in `index.html` concurrently on their individual feature branches and attempt to merge into `main` without synchronizing beforehand.

### 4.2 Merge Conflict Demonstration (Task 4b & 4c)

#### Conflicting File
- **File:** `index.html`

#### Conflict Markers Generated by Git
During the integration and pull of the remote changes (`b8240eb`), Git produced the following conflict markers in `index.html`:

```html
<<<<<<< HEAD
    <title>Student Information Management System</title>
=======
    <title>Student Information System</title>
>>>>>>> b8240ebf6a6f13deb1c10f31f76d8c066b8efda6
```

and across the body sections:

```html
<<<<<<< HEAD
    <header class="page-header">
        <h1>Student Information Management System</h1>
        <p class="subtitle">Collaborative Software Development Portal</p>
    </header>

    <main class="main-container">
        <!-- Integrated Form and Table Cards -->
        ...
    </main>
=======
    <h1>Student Information System</h1>

    <!-- Member A: Student Registration Form -->
    <section id="student-registration">
        <form id="registrationForm">
            ...
        </form>
    </section>
>>>>>>> b8240ebf6a6f13deb1c10f31f76d8c066b8efda6
```

#### How the Conflict was Resolved
1. **Inspection:** The Team Leader opened `index.html` to review competing changes from both branches (`HEAD` and remote `b8240eb`).
2. **Combination Decision:** Both the registration form (Member A) and the student records table (Member B) are essential core features. Rather than discarding either change, both were retained and unified inside a responsive container (`<main class="main-container">`), linking `style.css` and `script.js`.
3. **Marker Removal:** The markers (`<<<<<<< HEAD`, `=======`, and `>>>>>>> b8240eb...`) and duplicate `<!DOCTYPE html>` blocks were removed.
4. **Resolution Commit:**
   ```bash
   git add index.html
   git commit -m "Resolve merge conflict in index.html by integrating registration form and student records table"
   git push origin main
   ```

   ```bash
   git branch -a
   ```

4. **Verify Remote Repository Link:**
   ```bash
   git remote -v
   ```

### 5.2 Benefits of Using Git for Collaborative Development (Task 5c)

1. **Distributed Version Control & Complete Traceability:**  
   Every collaborator has a full history of the project locally. Git tracks author attribution, timestamps, and commit messages for every single modification, making it straightforward to review code, revert unintended bugs, and ensure individual accountability.

2. **Isolated Branching and Parallel Development:**  
   Git branches enable team members to build and test separate features (such as forms, tables, and styling) simultaneously in complete isolation without breaking or destabilizing the working `main` production codebase until pull requests are reviewed and approved.

## 7. How to Run the Application

1. Clone or download the repository:
   ```bash
   git clone https://github.com/Madagi001/student-information-system-G4.git
   cd student-information-system-G4
   ```
2. Open `index.html` in any modern web browser (Google Chrome, Firefox, Edge, Safari):
   - Double click `index.html` in your file explorer, OR
   - Use Live Server in your editor.
3. Test registering a new student by filling in the Student Name, Matriculation Number, and Programme, then click **Register Student**. The new record will appear dynamically in the table.
